## 知识类型

| 类型 | 用途 | 对应Agent场景 | 优先级 | 作者 |
| --- | --- | --- | --- | --- |
| **1. 政策规则** | 公司IT层面的“法律”，能不能、该不该、规范是什么、支持的范围 | 员工问：“我可以装xx软件吗？”“我能不能把显示名改成xx” | P0 | process onwer |
| **2. 操作流程** | 完成某件事的具体步骤，“怎么做” | 员工问：“如何申请新电脑？”“怎么重置密码？” | P0 | process onwer |
| **3. 常见问答** | 针对高频但无固定流程的问题，直接给出答案 | 员工问：“IT服务台电话多少？”“去哪修改用户名密码” | P0 | ODC |
| **4. 故障排查** | 出现错误时的诊断与解决步骤，升级渠道 | 员工问：“连不上WiFi怎么办？”“打印机不工作了。” | P1 |  |

### 类型1：政策规则（Policy）

**定义**：规范陈述，不包含操作步骤。

**什么时候需要写一条政策规则？**  
涉及到员工能否做这件事的判断

**一条政策规则应该包含以下5项内容**：

1.  **适用范围**：适用于谁、什么设备、环境。如果不适用某类场景，也要明确写出。
    
2.  **政策结论**：允许 / 禁止 / 必须 / 有条件允许。评判标准需定性/定量。
    
3.  **条件与例外**：如果有条件，条件是什么；如果有例外，谁可以审批。
    
4.  **违反后果**（可选）：如果不遵守会怎样。
    
5.  **负责人及更新日期**
    

**Example：**

**❌错误示例：**禁止员工显示名相似

[进度: 已完成]**正确示例：** 禁止员工显示名相似，相似的定义：显示名最短编辑距离 除以 较短显示名总长度，结果小于等于0.3

### 类型2：操作流程（Procedure）

**定义**：完成一件IT相关事务的**确定性步骤序列**。员工可以照着做。

**什么时候需要写一条操作流程？**  
当IT有固定的申请、变更、报修、领取等业务时。

**一条操作流程必须包含以下5项内容：**

1.  **触发条件**：什么情况下需要走这个流程（比如：新员工入职、电脑故障）
    
2.  **输入信息**：员工需要提前准备什么（工号、设备序列号、截图等）
    
3.  **步骤清单**：按顺序的每一步，每步必须可执行（动词+对象）
    
4.  **输出结果**：流程走完后会得到什么（新电脑、密码重置链接、审批通过）
    
5.  **预估耗时**：每个步骤的耗时或整体SLA
    

### 类型3：常见问答（FAQ）

**定义**：高频问道，不涉及流程或政策的，可直接套用的**事实型问题**。答案短小、确定、不分支。

**什么时候需要写FAQ？**  
当某个问题被问了超过5次，且答案可以用一句话说清。

**FAQ必须包含：**

*   典型问法（员工可能会怎么问）
    
*   标准答案（一句话）
    
*   补充链接或联系人（可选）
    

### 类型4：故障排查（Troubleshooting）

**定义**：针对一个具体的错误现象，给出诊断问题和解决步骤。

**什么时候需要写一条故障排查？**  
当某个报错或异常频繁出现且有固定解法时。

**一条故障排查必须包含：**

1.  **错误现象**：用户看到的错误提示或症状（精确引用文字更好）
    
2.  **适用环境**：哪些操作系统/软件版本/硬件型号下会出现
    
3.  **诊断步骤**：如何确认是这个问题（可选，但推荐）
    
4.  **解决步骤**：按顺序的修复动作
    
5.  **如果无效怎么办**：升级路径或替代方案
    

## 质量要求

#### 核心原则

1.  **唯一事实来源**：对于同一个IT流程（如“申请外包账号”），知识库中只能有一个经过流程Owner确认的“唯一版本”。任何一线客服补充的FAQ，必须能溯源到该唯一版本，否则视为无效或待确认。
    
2.  **可执行性优先**：入库的每条知识，Agent必须能根据它**直接回答**或**触发确定性的下一步动作**（如：给出链接、表单、等待天数、需要提供的字段）。模糊表述（如“如果电脑有问题”，“尝试清楚缓存重启”，“联系相关负责人”）禁止入库。
    
3.  **适用范围显式声明**：每条知识必须明确标注**适用的环境/对象**（如操作系统、设备类型、用户角色、网络环境等）。如果知识仅适用于某类场景，必须同时说明**不适用**的场景，或针对不同场景分别给出规则。否则代表**所有人所有情况都这样，没有任何例外**。
    
4.  **零矛盾要求**：入库前必须通过冲突检测。若新知识与已有知识存在逻辑冲突，必须标记并人工裁决，直至消除矛盾。
    

#### 文档格式

1.  视内容word文档或excel表格均可（excel注意不要合并单元格做复杂公式，表头名称清晰）。
    
2.  图片仅作辅助，文字必须完整
    

> 你可以附上流程图或步骤截图作为**辅助材料**（Agent回复员工时可以直接输出，或方便管理原理解内容），但**必须同时提供等价的文字描述**，确保Agent能从文字中提取全部必要信息。

| 场景 | 必须同时提供的文字内容 |
| --- | --- |
| 画了一个决策流程图 | 写出**决策逻辑的文字版**，如：“如果A，则执行X；如果B，则执行Y；如果C，则联系IT” |
| 截屏了某个系统界面的操作步骤 | 写出**步骤编号列表**，如：“第一步：点击‘开始’菜单；第二步：选择‘设置’...” |
| 拍了一张错误提示弹窗的照片 | 写出**错误弹窗中的完整文字**（如错误代码、提示信息），否则Agent无法匹配 |

## Tips：让AI帮你写

复制以下提示词，发给AI

> 我是企业IT【xx】流程负责人，目前在为我负责流程沉淀知识文档，这些知识将被放入我们公司的IT服务助手Agent的知识库，Agent会基于知识库的内容来回答员工的问题（RAG）。

> 请帮我写一条【政策规则 / 操作流程 / 常见问答 / 故障排查】类型的知识。

> 以下是我想表达的内容（想到什么写什么，不用排版）： 【在这里粘贴你脑中的策略、步骤、判断逻辑】

> 请按照以下要求输出：

1.  **全部使用文字表述**：所有决策步骤、条件分支、操作动作都必须用文字清晰写出。不要只输出图片或流程图。
    
2.  **如果某个地方用图片会更直观（例如界面截图、流程图）**：请在需要配图的位置**用加粗文字明确提示我**，格式为：“**建议配图：** \[描述图片内容\]”。同时，该图片所承载的信息仍需用文字完整描述一遍。
    
3.  **避免模糊词**：不要出现“尽快”、“可能”、“视情况”、“相关负责人”等模糊表达，改为具体数值、条件或明确的团队/角色。
    
4.  **明确条件分支**：如果存在“如果A，则X；如果B，则Y”的逻辑，请分条列出。
    
5.  **结构清晰**：对于操作流程，给出有序步骤；对于政策规则，明确结论和例外；对于FAQ，给出标准问题+标准答案；对于故障排查，给出现象+解决步骤。
    

> 输出后我会人工审核，你可以追问我缺失的信息。
