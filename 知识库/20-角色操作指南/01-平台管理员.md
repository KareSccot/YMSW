# 平台管理员操作指南

## 目标

读完这篇，作为平台管理员，你能部署 gitlab-management 服务、通过 API 建 GitLab 项目/用户、把项目归入团队 namespace，并守住 Common 层的维护边界。

## 你管什么

- **部署服务**：部署并维护 gitlab-management 服务。
- **建项目**：为业务线创建 GitLab 仓库，归入团队 namespace。
- **建用户**：开 GitLab 账号（内部开发者）。
- **维护 Common 层**：维护 `cicd-template` 仓库，改 `workflows/stages/rules/jobs`，走平台团队治理 MR。

## 流程要素

- **触发条件**：平台管理员需要部署 gitlab-management 服务、创建 GitLab 项目/用户、或维护 Common 层时。
- **输入信息**：GitLab 管理员权限、管理员 PAT、gitlab-management 项目代码、.env 配置文件。
- **输出结果**：gitlab-management 服务部署并验证健康；新项目/用户创建成功；Common 层 MR 提交走治理流程。
- **预估耗时**：部署服务约 10-20 分钟，建项目/用户约 2-5 分钟/个。以上为估算量级，非实测 SLA。
- **适用范围与不适用场景**：本篇适用于平台管理员的部署与维护职责。团队 Group 级变量配置和成员管理见「团队 Lead」，业务仓库接入见「业务线开发者」。

## 前置条件

- 你有 GitLab 管理员权限（建项目/建用户）。
- 有可用的 Personal Access Token（PAT，管理员权限），用于配 `GITLAB_TOKEN`。
- ⚠️ 注意：gitlab-management 当前**无鉴权中间件 + CORS 全开**（`api/main.py`），须确保服务只在内网可达。

## 操作步骤

### 0. 部署 gitlab-management 服务

```bash
cd gitlab-management/
python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env              # 编辑 .env 填入 GITLAB_URL 和 GITLAB_TOKEN
python run.py                     # 启动，默认监听 0.0.0.0:8000
```

- 环境变量（见 `.env.example`）：`GITLAB_URL`（公司 GitLab 实例）、`GITLAB_TOKEN`（管理员 PAT）。
- 验证：`curl http://localhost:8000/health` 返回 `{"status": "healthy"}`。
- API 文档：启动后访问 `http://localhost:8000/docs`（FastAPI 自动生成的 OpenAPI 文档）。
- ⚠️ 务必部署在内网，不要暴露公网端口。

### 1. 建项目并归入团队 namespace

调用 projects 路由，`namespace_id` 决定项目归属哪个团队：

```bash
curl -X POST http://<gitlab-mgmt>/api/projects/ \
  -H "Content-Type: application/json" \
  -d '{
    "name": "my-service",
    "namespace_id": 12
  }'
```

- 请求模型 `CreateProjectRequest`：`name`（必填）、`namespace_id`（选填，不填则建在个人 namespace）。
- 响应：`{id, name, path, web_url, visibility}`，项目默认 `visibility: private`。

### 2. 建用户

调用 users 路由开账号（内部开发者）：

```bash
curl -X POST http://<gitlab-mgmt>/api/users/ \
  -H "Content-Type: application/json" \
  -d '{
    "email": "dev@wuxibiologics.com",
    "username": "dev_zhang",
    "name": "张三",
    "password": "<强密码>"
  }'
```

- 请求模型 `CreateUserRequest`：`email` / `username` / `name` / `password`（均必填）。
- 创建时带 `skip_confirmation: true`，跳过邮箱确认。
- 响应：`{id, username, name, email, state, web_url}`。
- ⚠️ **外包用户**：会议明确"禁止 AI 代码开发"的禁令针对外包——即外包人员不得使用 Claude Code / Cursor / Copilot 等工具写代码。给外包开账号须遵守此边界，仅授予必要的读/部署权限。

### 3. 查项目/查用户

```bash
# 列所有项目（可按 namespace 过滤）
curl http://<gitlab-mgmt>/api/projects/?namespace_id=12

# 查单个项目
curl http://<gitlab-mgmt>/api/projects/<project_id>

# 列所有用户（默认只列 active）
curl http://<gitlab-mgmt>/api/users/

# 查单个用户
curl http://<gitlab-mgmt>/api/users/<user_id>
```

### 4. 维护 Common 层

- 在 `cicd-template` 仓库提 MR。
- 改 `rules/`、`approval/` 等触及审批门禁的内容须走安全层 Pro 复审。
- 详见 「Common 层」。

## 代码示例

见上方各步骤 curl 示例。Python 调用示例：

```python
import requests
BASE = "http://<gitlab-mgmt>/api"

# 建项目
requests.post(f"{BASE}/projects/", json={"name": "my-service", "namespace_id": 12}).json()

# 建用户
requests.post(f"{BASE}/users/", json={
    "email": "dev@wuxibiologics.com",
    "username": "dev_zhang", "name": "张三", "password": "..."
}).json()
```

## 注意事项

- **服务无鉴权 + CORS 全开**：gitlab-management 自身没加 JWT/认证中间件，任何能访问到该服务的人都能调所有 API。**务必部署在受控内网**，或在前置网关加鉴权。这是当前最大安全风险。
- **`ssl_verify=False`**：GitLab client 关闭了 SSL 校验，内网自签证书场景可用，但须确认链路可信。
- **token 权限**：`GITLAB_TOKEN` 用的是有管理员权限的 PAT，泄露风险高，须妥善保管，定期轮换。
- **Common 层改动是高治理动作**：改 Common 层影响全公司业务线，走平台团队 MR + 必要时安全层 Pro。
- **外包边界**：给外包开账号/加成员须遵守"外包禁止 AI 代码开发"的会议要求。
