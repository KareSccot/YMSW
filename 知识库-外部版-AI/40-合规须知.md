# 40 - 合规须知


## 发版审批要求

**适用范围**：所有需要发布到生产环境的 CI/CD 流水线。

**政策结论**：发版到生产环境必须经过两级审批，否则不允许部署。

**条件与例外**：
- **Release Approval**：必须由发版人之外的第二人审批。发版人本人不能执行审批操作。
- **AppSec Approval**：安全团队审批，检查安全扫描结果。
- 审批阶段设置为 `allow_failure: false`，未通过审批时流水线阻塞。
- 紧急情况可联系 DevOps 主管协调加速审批流程。

**违反后果**：
- 未通过审批直接部署 → 流水线阻塞，无法部署
- 绕过审批 → 违反安全合规要求，可能触发安全事件
- 生产事故 → 追溯责任，发版人和审批人共同承担

**负责人及更新日期**：
- 政策负责人：DevOps 团队
- 安全审批负责人：AppSec 安全团队
- 更新日期：2026-08-11

**升级路径**：
- 审批人不在线 → 联系团队 Tech Lead 协调替代审批人
- 安全审批疑问 → 联系安全团队 `#security-support`
- 政策疑问 → 联系 DevOps 团队

## 安全扫描要求

**适用范围**：所有接入 CI/CD 流水线的项目。

**政策结论**：所有项目必须启用安全扫描，扫描结果作为发版审批的参考依据。

**条件与例外**：
- 必须启用的扫描类型（根据项目类型选择）：
  - **SAST**：静态应用安全测试，扫描源码漏洞
  - **SCA**：软件组成分析，扫描第三方依赖漏洞
  - **Docker Scan**：容器镜像安全扫描（仅容器化项目）
  - **ThreatModeling**：威胁建模分析
- 安全扫描允许失败（`allow_failure: true`），但扫描结果必须被审阅
- 安全报告自动生成并发送到触发人的邮箱

**违反后果**：
- 未启用安全扫描 → 发版审批可能被安全团队拒绝
- 扫描发现高危漏洞未处理 → 安全团队可要求修复后再发版
- 多次违规 → 安全团队介入，项目可能被暂停

**负责人及更新日期**：
- 政策负责人：安全团队（AppSec）
- 扫描工具维护：DevOps 团队
- 更新日期：2026-08-11

**升级路径**：
- 扫描工具配置问题 → 联系 DevOps 团队
- 漏洞修复咨询 → 联系安全团队 `#security-support`
- 申请跳过扫描 → 联系安全团队负责人

## 敏感信息管理规范

**适用范围**：所有在 CI/CD 流水线中使用敏感信息的项目。

**政策结论**：敏感信息（Token、密码、SSH Key、证书）不得写入代码仓库，必须通过 GitLab CI/CD Variables 注入。

**条件与例外**：
- ✅ **允许**：通过 GitLab Settings → CI/CD → Variables 配置的 Masked 变量
- ✅ **允许**：CI/CD 预定义变量（如 `$CI_PROJECT_NAME`、`$CI_PIPELINE_ID`）
- ✅ **允许**：环境级变量（不同环境使用不同变量，如 `DEV_SSH_KEY` vs `PROD_SSH_KEY`）
- ❌ **禁止**：将 Token 或密码硬编码在 `.gitlab-ci.yml` 或代码文件中
- ❌ **禁止**：在日志中输出环境变量值（除非调试完成后立即删除）
- ❌ **禁止**：将 `.env` 文件提交到代码仓库

**违反后果**：
- 敏感信息泄露 → 立即触发安全事件，需要轮换所有受影响凭证
- 代码审查发现违规 → MR 被拒绝，要求修改后重新提交
- 严重泄露 → 安全团队追责，项目可能被暂停

**负责人及更新日期**：
- 政策负责人：安全团队
- 更新日期：2026-08-11

**升级路径**：
- 发现敏感信息泄露 → 立即联系安全团队 `#security-support`
- 需要新增变量 → 联系 DevOps 团队
- 凭证轮换需求 → 联系 DevOps 团队处理

## 团队镜像构建规范

**适用范围**：所有在 team-cicd 层配置 Docker 容器构建的团队项目。

**政策结论**：团队自定义 Docker 构建必须遵循统一的镜像构建规范，确保镜像安全性和可追溯性。

**条件与例外**：

### 允许的构建参数
- ✅ `DOCKER_BUILD_ARGS` 中传递 `BUILD_FOLDER`、`ARTIFACT_FOLDER`、`PACKAGE_NAME`、`SERVICE_PORT` 等非敏感参数
- ✅ 使用团队级默认值（如 `SERVICE_PORT: 8080`）减少应用项目重复配置
- ✅ 使用 `image` 字段指定自定义构建镜像（如 JDK 21 + Maven 组合镜像）
- ✅ 使用 `BEFORE_DEBUGGING_TIME` 调试变量（仅在调试阶段使用，完成后删除）

### 禁止的操作
- ❌ 在 `DOCKER_BUILD_ARGS` 中传递 Token、密码、证书等敏感信息
- ❌ 在团队工作流文件中硬编码镜像仓库认证信息
- ❌ 使用 `latest` 标签作为构建镜像引用（必须指定具体版本标签）
- ❌ 在 `BEFORE_DEBUGGING_TIME` 中输出环境变量值到日志（调试完成后立即禁用）

### 镜像标签规范
- 自动生成的镜像标签格式：`<registry>/<namespace>/<service-name>:<branch>-<pipeline-id>`
- 团队不得自定义镜像标签格式，必须使用平台自动生成的标签
- 镜像推送由平台自动完成，团队无需手动配置仓库凭证

**违反后果**：
- 敏感参数通过 `DOCKER_BUILD_ARGS` 传递 → 泄露风险，需立即轮换受影响凭证
- 使用 `latest` 标签 → 构建镜像不可追溯，安全团队可要求修复
- 日志输出敏感信息 → 触发安全事件，需清理日志并轮换凭证

**负责人及更新日期**：
- 政策负责人：DevOps 团队
- 镜像仓库管理：平台运维团队
- 更新日期：2026-08-11

**升级路径**：
- 需要自定义 Docker 构建参数 → 联系 DevOps 团队评估
- 镜像仓库权限问题 → 联系平台运维团队
- 构建镜像版本更新 → 联系 DevOps 团队同步更新
