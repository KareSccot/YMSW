# 故障排查

## 目标
读完本章后，开发者能独立诊断和解决 CI/CD 流水线中的常见故障。

## 前置条件
- 项目已接入 CI/CD 流水线
- 有 GitLab 项目访问权限
- 了解流水线各阶段的基本概念

## 操作步骤

### 流水线启动失败
**诊断步骤**：
1. 检查 `.gitlab-ci.yml` 文件是否存在
2. 使用 GitLab CI Lint 验证语法
3. 检查 `include` 路径格式是否正确
4. 查看流水线日志，定位具体错误

**解决步骤**：
1. 缺失文件 → 从模板复制
2. 语法错误 → 使用 CI Lint 修复
3. 路径错误 → 修正为正确的相对路径
4. Runner 不可用 → 等待恢复或联系 DevOps 团队

### 构建阶段失败
**诊断步骤**：
1. 查看构建日志末尾的错误信息
2. 检查 `BUILD_TOOL` 变量是否正确
3. 确认 `BUILD_FOLDER` 和 `ARTIFACT_FOLDER` 设置正确

**解决步骤**：
1. 编译错误 → 修复代码，重新提交
2. 变量错误 → 修改 GitLab CI/CD Variables
3. 版本不兼容 → 调整工具版本

### 部署阶段失败
**诊断步骤**：
1. 查看部署日志
2. 检查部署环境变量配置
3. ArgoCD 部署：查看 ArgoCD UI
4. VM 部署：检查 SSH 连接

**解决步骤**：
1. 镜像问题 → 修复容器构建阶段
2. 变量缺失 → 补全配置
3. SSH 失败 → 检查网络和密钥配置

### 安全扫描问题
**诊断步骤**：
1. 检查安全扫描日志
2. 确认 SAST/SCA 配置参数
3. 检查扫描超时设置

**解决步骤**：
1. 配置缺失 → 联系安全团队获取配置
2. 超时 → 调整超时时间
3. 误报 → 在安全审核时说明

## 注意事项
- 查看日志时关注日志末尾的关键错误信息
- 生产环境部署失败不要多次重试，先定位原因
- 安全扫描允许失败，但结果必须被审阅
- 敏感信息不要输出到日志中

## 升级路径（搞不定找谁）
- 构建问题 → 提供完整日志，联系 DevOps 团队 `#devops-support`
- 部署问题 → 提供流水线链接，联系 DevOps 团队
- 安全扫描问题 → 联系安全团队 `#security-support`
- 紧急回滚 → 联系 DevOps 团队立即处理
