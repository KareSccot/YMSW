# 新手接入指南

## 目标
读完本章后，新手开发者能独立完成项目的 CI/CD 接入，包括创建 `.gitlab-ci.yml`、配置构建工具、构建 Docker 镜像和部署应用。

## 前置条件
- 已完成前置条件（见 00-前置条件.md）
- 项目 GitLab 地址和权限已就绪

## 操作步骤

### 1. 接入 CI/CD 流水线
1. 确认项目已在 GitLab 上创建，开发者拥有至少 Developer 角色
2. 根据项目类型选择工作流模板：
   - 应用程序项目 → 引用 `app-workflow.yml`
   - IaC 项目 → 引用 `iac-workflow.yml`
3. 在项目根目录创建 `.gitlab-ci.yml`：
   ```yaml
   include:
     - local: workflows/app-workflow.yml
   ```
4. 在 GitLab CI/CD Variables 中配置构建参数：
   - `BUILD_TOOL`: 构建工具（gradle / mvn / pnpm）
   - `BUILD_FOLDER`: 源码目录路径
   - `ARTIFACT_FOLDER`: 制品输出目录
   - `SERVICE_REPOSITORY`: 镜像仓库命名空间
   - `TEAM`: 所属团队名
5. 提交代码并推送，流水线自动触发

### 2. 配置构建工具
- **Gradle 构建**：设置 `BUILD_TOOL: "gradle"`，默认使用 JDK 21 + Gradle，输出 `*.jar` 制品
- **Maven 构建**：设置 `BUILD_TOOL: "mvn"`，默认使用 JDK 21 + Maven，输出 `*.jar` 制品
- **pnpm 构建**：设置 `BUILD_TOOL: "pnpm"`，默认使用 Node.js 18 + npm，输出前端构建产物

### 3. 构建 Docker 镜像
1. 准备 Dockerfile 在项目根目录
2. 设置 `BUILD_CONTAINER: "true"` 和 `SERVICE_REPOSITORY`
3. 提交代码，流水线自动构建镜像并推送到镜像仓库
4. 镜像标签格式：`<registry>/<namespace>/<service-name>:<branch>-<pipeline-id>`

### 4. 部署到 K8s（ArgoCD）
1. 确保容器镜像构建完成
2. 在 Pipeline 页面手动触发对应环境的 deploy 按钮
3. 系统自动更新 GitOps 仓库中的镜像版本
4. ArgoCD 自动同步到目标环境
5. 在 ArgoCD UI 查看部署状态

### 5. 部署到 VM（Docker Compose）
1. 准备 `docker-compose.yml` 在项目根目录
2. 配置 SSH 连接信息在 GitLab CI/CD Variables 中
3. 在 Pipeline 页面手动触发部署
4. 部署完成后在目标服务器验证容器运行状态

## 注意事项
- 镜像构建需要设置 `BUILD_CONTAINER: "true"`，否则默认跳过
- 部署操作是手动触发的，不会自动执行
- 生产环境部署需要审批
- 敏感信息（SSH Key、证书）通过 GitLab CI/CD Variables 注入，不写入代码

## 升级路径（搞不定找谁）
- 构建失败 → 检查构建工具版本和参数，联系 DevOps 团队 `#devops-support`
- 镜像推送失败 → 确认 `SERVICE_REPOSITORY` 配置
- 部署失败 → 联系 DevOps 团队
- 权限问题 → 联系项目负责人或团队 Tech Lead
