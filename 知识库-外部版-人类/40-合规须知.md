# 合规须知

## 目标
读完本章后，开发者能了解 CI/CD 流水线的合规要求，包括发版审批、安全扫描和敏感信息管理规范。

## 前置条件
- 项目已接入 CI/CD 流水线
- 开发者了解基本的安全意识

## 操作步骤

### 发版审批要求
1. 发版到生产环境前，Release Pipeline 必须经过两级审批
2. **Release Approval**：发版人本人不能审批，必须由第二人审批
3. **AppSec Approval**：安全团队审核扫描结果
4. 审批阶段设置为 `allow_failure: false`，未通过则流水线阻塞
5. 审批通过后，手动部署到 UAT → 验证 → 手动部署到生产

### 安全扫描要求
1. 所有项目必须启用安全扫描，根据项目类型选择扫描方式：
   - SAST：静态源码安全扫描
   - SCA：第三方依赖安全扫描
   - Docker Scan：容器镜像安全扫描（仅容器化项目）
   - ThreatModeling：威胁建模分析
2. 安全扫描允许失败，但结果必须被审阅
3. 安全报告自动生成并发送到触发人的邮箱

### 敏感信息管理规范
1. **禁止**将 Token、密码、SSH Key、证书写入代码仓库
2. 敏感信息必须通过 GitLab CI/CD Variables 配置（Masked 变量）
3. 不同环境使用不同变量前缀（如 `UAT_SSH_KEY` vs `PROD_SSH_KEY`）
4. 禁止在日志中输出环境变量值
5. 禁止将 `.env` 文件提交到代码仓库

## 注意事项
- 审批不能由发版人自己执行
- 安全扫描发现高危漏洞，安全团队有权要求修复后再发版
- 敏感信息泄露是安全事件，需立即报告
- 紧急情况可联系 DevOps 主管协调加速审批

## 升级路径（搞不定找谁）
- 审批人不在线 → 联系团队 Tech Lead 协调替代
- 安全审批疑问 → 联系安全团队 `#security-support`
- 发现敏感信息泄露 → 立即联系安全团队
- 政策疑问 → 联系 DevOps 团队
