## UAT 分支名大小写

### 内部版

模板中安全扫描（DockerScan/SCA/ThreatModeling/GenSecurityReport）的触发条件是 `$CI_COMMIT_BRANCH == "UAT"`（大写）。若分支名使用小写 `uat`，安全扫描不会触发，构建部署不受影响。建议分支名使用大写 `UAT` 对齐模板规则。

### 外部版-AI

模板中安全扫描（DockerScan/SCA/ThreatModeling/GenSecurityReport）的触发条件是 `$CI_COMMIT_BRANCH == "UAT"`（大写）。若分支名使用小写 `uat`，安全扫描不会触发，构建部署不受影响。建议分支名使用大写 `UAT` 对齐模板规则。

### 外部版-人类

安全扫描（DockerScan/SCA/ThreatModeling）只在分支名为 `UAT`（大写）时触发。若分支名用小写 `uat`，构建部署正常但安全扫描跳过。建议新建预发布分支时直接使用大写 `UAT`。

## 前端产物路径（vite）

### 内部版

vite 构建产物默认输出到 `dist/` 目录，非 `build/`。前端项目需在 `.gitlab-ci.yml` 中设 `ARTIFACT_FOLDER: "dist"`，否则 `build-container` 的 `docker build` 会因找不到产物而失败。ariba 前端已验证此配置。

### 外部版-AI

vite 构建产物默认输出到 `dist/` 目录，非 `build/`。前端项目需在 `.gitlab-ci.yml` 中设 `ARTIFACT_FOLDER: "dist"`，否则 `build-container` 的 `docker build` 会因找不到产物而失败。

### 外部版-人类

vite 构建产物默认输出到 `dist/` 目录而非 `build/`。前端项目接入时须在 `.gitlab-ci.yml` 中设 `ARTIFACT_FOLDER: "dist"`，否则镜像构建会因找不到产物而失败。

## 前端构建环境选择

### 内部版

ariba 前端 `build-app` 按分支名自动选择构建 profile：dev 分支 → `build:test`，UAT 分支 → `build:uat`，Master 分支或 tag → `build:prod`。接入前端项目时注意：分支命名需与 build script 的 `npm run build:<env>` 对应，否则构建失败。

### 外部版-AI

ariba 前端 `build-app` 按分支名自动选择构建 profile：dev 分支 → `build:test`，UAT 分支 → `build:uat`，Master 分支或 tag → `build:prod`。接入前端项目时注意：分支命名需与 build script 的 `npm run build:<env>` 对应，否则构建失败。

### 外部版-人类

ariba 前端按分支名自动选择构建 profile：dev 分支跑 `build:test`，UAT 分支跑 `build:uat`，Master 分支或 tag 跑 `build:prod`。分支命名需与 `npm run build:<env>` 对应，否则构建报错。

## 前端 nginx 端口

### 内部版

ariba 前端 nginx 容器监听 80 端口（`SERVICE_PORT: 80`），SSL 终止在 K8s Ingress 层。若自建 nginx 配置，注意 `listen` 指令写死的端口（默认 80），且容器内非 root 用户无法绑定 <1024 端口。修改端口需同时改 `nginx.conf` 的 `listen` 和 `SERVICE_PORT` 变量。

## 分支名与安全扫描触发

### 内部版

当前模板安全扫描只对 `UAT` 分支触发。若团队使用其他分支名（如 `release`、`main`）做预发布验证，安全扫描不会运行。需在团队工作流中覆盖对应 job 的 rules，或统一使用 `UAT` 分支名。
