# 对齐标准（maintain 层）

> 本文件是 skill 体系的对齐标准，所有子 skill 维护时必须遵守。改子 skill 必须先对齐标准 + 跑回归才上线，不能各管各最后拼装打架。

## 一、3 个标准化

### 标准 1：接口契约格式
每个子 skill 的 `## 接口契约` 必须含 4 张表，顺序固定：
1. **输入参数**（参数名 | 含义 | 来源：前置收集/本模块提问/父传入 | 默认值）
2. **输出产物**（文件名 | 落地位置 | 格式）
3. **依赖**（依赖哪些模块的输出 / 依赖哪些 references 模板）
4. **边界**（本模块不做 X，转交 Y）

### 标准 2：提问协议格式
- 父 SKILL.md 统一用 `§提问协议` 通用规则（有结构化提问工具用卡片，没有用编号纯文本列表；必须停下等用户回答；分批问不一次性糊给）
- 子模块提问统一命名 `Batch N：主题（X 题）`
- 每题格式固定：`题干 + 选项列表 + 一句话判断标准 + 具体例子`
- 跨模块共用的参数（如 SERVICE_NAME）只在入口模块收集一次，父 SKILL.md 传给复用模块，**复用模块不再提问**

### 标准 3：模板格式（已统一，维持现状）
- 占位符统一用 `${UPPER_SNAKE}`（envsubst/shell 扩展风格）——已验证 16 模板全一致，无 `{{}}` / `__X__` 混用。**维持现状，不要改成 `{{}}`**（会破坏 envsubst/bash 语义，模板跑不起来）
- 模板文件名统一后缀：`.example`（示例）/ `.template`（带占位符）/ `.yml.example`
- 模板开头必须有注释段说明：用途 / 对应哪个 capability 模块 / 占位符清单（部分模板缺，要补）

## 二、回归门控清单（改完子 skill 上线前必跑）

每次改子 skill / 模板，commit 前必须全过：

- [ ] **路径可达**：SKILL.md 里所有 `Read capabilities/...` / `resources/references/...` 路径真实存在
- [ ] **接口契约一致**：改了输入/输出参数，4 张表同步更新；依赖模块的契约没被破坏
- [ ] **提问协议题号**：Batch 编号连续无跳号；跨模块共用参数只在一处收集
- [ ] **模板占位符**：改了占位符，所有引用该模板的模块同步改；占位符符合标准 3（`${UPPER_SNAKE}`，不混入 `{{}}`/`__X__`）
- [ ] **编码**：无 BOM；CJK 字符完整（opencode 写文件易乱码，单独验）
- [ ] **backtick**：代码块 backtick 配对成偶数（opencode 易丢 backtick）
- [ ] **主流程走查**：从 SKILL.md 入口到该模块产出，端到端走一遍无断链
- [ ] **用户/平台边界**：用户 skill 里没混入平台维护逻辑；平台 skill 里没混入用户引导
- [ ] **user/platform 同步**：改 platform 模块时检查 user 侧是否需要同步（maintain 层建立后此项消除，改一处两处引用同步）

## 三、维护流程（平台工程师改子 skill 的标准动作）

1. 改子 skill / 模板（在 maintain/ 里改，唯一真源）
2. 更新该模块 `## 接口契约` 4 张表（标准 1）
3. 跑回归门控清单（第二节）
4. 全过 → commit → 主 SKILL.md 自动感知（调度链路 Read 路径没变就不用改主 skill）
5. 若改了模块路径或新增模块 → 同步改主 SKILL.md 调度表

## 四、质量标尺

所有 skill 按以下 7 项标准编写并通过终审：

1. **触发条件清单**（description 列用户原话触发句 + 负面边界，非一句概括）
2. **执行契约开篇**（先抓 N 步主干，再读细节）
3. **决策点抽表**（可枚举分支→表；开放判断→叙事，不硬抽表）
4. **红线集中**（真红线集中前置 + 拒绝动作；不造凑数红线）
5. **异常分支**（每步命名失败模式 + 恢复动作）
6. **Agent 视角写作**（执行契约不是文档；guidance 不是脚本）
7. **自包含 + 条件化跨引用**（运行时不读外部文档；跨 skill 引用带"if that skill is present"）
